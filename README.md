# Shelter Games

Дитяча гра на **PixiJS**: повітряна кулька падає, а гравці-долоні мають не дати їй
торкнутися підлоги. Кулька — не спрайт і не коло: це справжнє м'яке тіло, яке
мнеться від удару, пружинить назад і відлітає в бік ляпаса.

## Запуск

```bash
npm install
npm start          # збирає клієнт і піднімає сервер на http://localhost:8090
```

Сервер слухає на всіх інтерфейсах, тож з іншого пристрою в тій самій мережі гра
відкривається за `http://<IP-цього-комп'ютера>:8090/`.

## На весь екран з телефона

Світ гри горизонтальний (1200×800), а телефон у руці вертикальний: `layout()`
вписує світ цілком, тож у портреті гра стискається у смужку посеред екрана.
Тому на дотикових пристроях кнопка «Грати» заразом **просить повний екран і
повертає екран у ландшафт** — обидва виклики дозволені лише всередині жесту
користувача, тож живуть у тому самому обробнику. У кутку HUD є й кнопка ⛶, щоб
вийти чи зайти вручну; іконка стежить за системними виходами (Esc, жест) через
подію `fullscreenchange`.

Довге натискання на планшеті відкривало системну виноску («Скопіювати»,
«Поділитись») просто посеред удару, тож контекстне меню прибране в усіх режимах
разом із виділенням тексту (`-webkit-touch-callout: none`). Єдиний виняток —
поля коду кімнати: там воно потрібне для «Вставити».

На iPhone Fullscreen API немає зовсім — Safari дає його лише відео, і кнопка
там просто ховається. Повний екран на ньому дає «Поділитись → На початковий
екран»: заради цього в `<head>` лежать `apple-mobile-web-app-*`, і з іконки гра
відкривається без адресного рядка.

## Плата за удар: важка долоня

Долоня **тілесна завжди** — відбити кульку можна будь-коли. Але після кожного
удару вона на `slowTime` (0.3 с) обважнює і стає **вдвічі повільнішою**:

* `slowFactor` 0.5 — удвічі млявіше слухається курсора;
* `slowSpeed` 750 px/с — стеля швидкості замість звичайних 2600 (це рівно
  половина клавіатурної `keySpeed`).

Одного лише млявішого `follow` для цього замало: за курсором, що їде рівномірно,
долоня однаково розганяється до його швидкості, просто з більшим відставанням.
Тому обважнілій ріжеться ще й сам шлях за кадр — інакше «вдвічі повільніше»
відчувалось би тільки на ривку. Заміряно: за ціллю, що їде 1500 px/с, свіжа
долоня тримає її швидкість, обважніла — рівно 750 px/с.

Через це слабшає й сам ляпас, бо він рахується від швидкості долоні. Заміряно,
швидкість кульки після удару на повному замаху: свіжою долонею 2610 px/с,
обважнілою — 1181 px/с. Тобто обважніла рука **б'є, але вдвічі слабше**.

Очко зараховується лише **свіжій** долоні. Обважніла відбиває кульку без очка —
інакше можна було б підпирати кульку впритул і молотити по ній по 5–6 очок за
секунду. Тримати її долонею як підставкою теж не виходить: кулька кругла і
з'їжджає вбік (30 с нерухомої долоні — 8 очок і кінець гри).

Раніше плата за тап була інша: 0.3 с долоня була **безтілесною**, і кулька
пролітала крізь неї. Тепер замість «нічим бити» — «важко бити».

## Сила ляпаса

Ляпас — це **один поштовх у момент дотику**, пропорційний швидкості долоні
(`slapBase` + швидкість × `slapPerSpeed`, зі стелею `slapCap`).

Раніше цей поштовх додавався на кожному підкроці контакту, і виходило рівно
навпаки: сила залежала не від швидкості долоні, а від того, скільки вона
провисить на кульці. Повільна долоня-поличка торкалась ~1700 підкроків і
підкидала кульку на 200 px, а різкий ляпас встигав 2 підкроки, після чого
тодішній кулдаун робив долоню безтілесною — і вона пролітала крізь кульку
наскрізь. Заміряно, підйом кульки від одного удару:

| швидкість долоні | було | стало |
|---|---|---|
| 300 px/с | 367 px | 402 px |
| 800 px/с | 48 px | 526 px |
| 1200 px/с | 18 px | 473 px |
| 3000 px/с | 64 px | 506 px |

Поштовх додається **всім точкам оболонки однаково**. Спільний зсув швидкості не
змінює взаємних швидкостей точок, тож оболонку не розірве, хай яким сильним буде
удар — на відміну від імпульсу в окремі точки контакту (див. нижче).

Напівзахід «лишити долоню перешкодою, але прибрати удар» теж не годиться —
перевірено: долоня тягне за собою точки контакту, решта кульки відстає, і
оболонку розриває (швидкість точок стрибала до 160 000 px/с). Саме тому
обважніла долоня не «безсила перешкода», а звичайна долоня зі слабшим ляпасом:
вона й далі віддає кульці імпульс, тож не тягне оболонку за собою. Від смикання
її додатково страхує стеля швидкості в `advanceHand` і `maxStretch`.

## Публічне посилання

```bash
npm run share
```

Піднімає гру і відкриває на неї безкоштовне https-посилання через Cloudflare
quick tunnel — друзі можуть грати звідки завгодно, не лише з твоєї мережі.
Команда сама надрукує адресу виду `https://…​.trycloudflare.com`.

Два застереження:

* посилання **тимчасове** — воно живе, поки працює команда, і після
  перезапуску буде новим;
* поки тунель відкритий, твій комп'ютер доступний ззовні за цією адресою.
  `Ctrl+C` закриває і тунель, і сервер.

**Увага:** домени `*.trycloudflare.com` часто позначаються браузерами як
підозрілі (їх масово використовують для фішингу), тож посилання може не
відкритись у декого з друзів. Тоді потрібен нормальний хостинг — див. нижче.

Один раз треба завантажити сам `cloudflared` (без sudo, лягає в `bin/`,
яка не потрапляє в git):

```bash
mkdir -p bin && curl -fsSL -o bin/cloudflared \
  https://github.com/cloudflare/cloudflared/releases/latest/download/cloudflared-linux-amd64 \
  && chmod +x bin/cloudflared
```

### Постійний сайт: GitHub Pages

```bash
npm run deploy:pages
```

Збирає гру і кладе її в гілку `gh-pages` — сайт живе за адресою
`https://<користувач>.github.io/<репозиторій>/` і не залежить ні від увімкненого
комп'ютера, ні від тунелю. Pages віддають **лише статику**, тож сам по собі
такий сайт — це одиночна гра і гра вдвох за одним екраном: сервера кімнат там
нема, і кнопки кімнат ховаються (клас `no-online`).

### Кімнати на постійному сайті

Сервер кімнат мусить десь бути, і найдешевший варіант — твій же комп'ютер:

```bash
npm run share
```

Ця команда, крім тунелю, кладе поруч зі сторінкою файл `ws.json` з адресою
сокета (гілка `gh-pages`, через `gh`). Сторінка на github.io читає його при
завантаженні — і якщо запис свіжий, вмикає кімнати **в усіх трьох режимах**:
звичайному, хардкорі й тім-апі. `Ctrl+C` прибирає файл, і сайт знову лишається
одиночною грою.

Три дрібниці, які варто знати:

* Pages збираються близько хвилини, тож кімнати на сайті з'являються не в ту ж
  секунду, коли команда надрукувала адресу;
* запис старший за 12 годин клієнт ігнорує — тунель стільки не живе, і краще не
  показати кімнат, ніж показати кнопку в нікуди;
* `npm run deploy:pages` переписує гілку форсом, але `ws.json` при цьому
  переносить — інакше викладка посеред спільної гри вимикала б кімнати.

Якщо сервер має жити без твого комп'ютера, лишається звичайний хостинг
(див. «Розгортання на хостингу»), а адреса вбудовується у збірку:

```bash
VITE_WS_URL=wss://моя-гра.onrender.com npm run deploy:pages
```

Для розробки з гарячим перезавантаженням — два термінали:

```bash
npm run server     # мультиплеєр на :8090
npm run dev        # клієнт на :5173 (сам знайде сервер на :8090)
```

## Розгортання на хостингу

Якщо тимчасове посилання блокується браузером, гру варто підняти на справжньому
хостингу — домен там із нормальною репутацією, і посилання працює завжди.

У репозиторії вже лежить усе потрібне: `Dockerfile` (для будь-якого
контейнерного хостингу) і `render.yaml` (готовий опис сервісу для Render).
Сервер читає порт зі змінної `PORT`, як того й вимагають хостинги.

```bash
gh auth login                       # один раз
git init && git add -A && git commit -m "Кулька"
gh repo create baloon-tapper --private --source=. --push
```

Далі на render.com: **New → Blueprint**, вибрати цей репозиторій — Render
підхопить `render.yaml` сам. Ім'я сервісу там уже задане, тож адреса виходить
**https://balloon-tapper.onrender.com** — справжній домен зі справжнім
сертифікатом, тож жодних попереджень у браузері, на відміну від тимчасового
тунелю вище.

Два зауваження про безкоштовний план: сервіс **засинає** після 15 хвилин без
відвідувачів (перше відкриття після паузи — секунд тридцять), і кімнати
мультиплеєра живуть у пам'яті процесу, тож після засинання код кімнати треба
створювати наново.

## Меню

Меню екранне: головний екран — це п'ять кнопок («Класика», «Хардкор», «Тім-ап»,
«Магазин», «Як грати»), і кожна веде на свій екран із «←» назад. Раніше все жило
однією довгою карткою: кнопка «Грати одному» губилась між двома рядами магазину,
а до тім-апа доводилось прокручувати півекрана — на телефоні в ландшафті це
особливо боляче.

Кожен режим забирає свій екран цілком, разом зі своїм кольором (хардкор
темний, тім-ап зелений), описом, рядом покупок і кімнатою. Магазин зібрав те,
що купується за монети, — кульки й перчатки; персонажі й командні переваги
лишились у своїх режимах, бо купуються за черепи й жетони, які там і дають.

Дві дрібниці, на яких це тримається:

* екран перемикає будь-яка кнопка з `data-go` — розмітка, а не код, вирішує,
  куди вона веде, і «←» це та сама кнопка з `data-go="home"`;
* гаманець світиться одразу в чотирьох місцях (головний екран, магазин, острів
  режиму, HUD), тож оновлюється за `data-w`, а не за id — додати ще одне місце
  можна самою розміткою.

Посилання-запрошення відкриває екран свого режиму ще до з'єднання: якщо кімната
виявиться повною або зв'язок обірветься, гравець опиниться саме там, де лежить
поле для коду. `Esc` у меню — це крок назад, на головний екран.

## Режими

| Режим | Як грати |
|---|---|
| **Одному** | миша / дотик, або `WASD` |
| **Вдвох за одним комп'ютером** | Гравець 1 — `WASD`, Гравець 2 — стрілки. На сенсорному екрані — просто два пальці |
| **Мультиплеєр між браузерами** | **до 4 гравців.** «Створити кімнату» → роздай друзям 4-символьний код або посилання `?room=КОД` |
| **☠ Хардкор** | те саме — одному, вдвох чи кімнатою, — але зі своїм світом, своїми персонажами і своєю валютою (див. нижче) |
| **🤝 Тім-ап** | кооператив: кулька ходить по руках, і двічі поспіль тапати не можна. Вдвох за одним комп'ютером або кімнатою до 4 |

Кімнати влаштовані однаково в **усіх трьох режимах**: у кожного свого острова в
меню є пара «Створити кімнату» + поле коду з кнопкою «Приєднатись». Код
універсальний — по ньому заходиш у будь-яку кімнату, а грати будеш у тому
режимі, у якому її створили (див. «Хардкор у мультиплеєрі»).

Можна одразу відкрити потрібний режим: `?mode=solo`, `?mode=local2`,
`?mode=hardcore`, `?mode=hardcore2`, `?mode=team`, `?room=КОД`. Створити кімнату
з посилання — `?host=hardcore` (або `team`, або без значення — звичайна).
Запрошення, яке дає кнопка «Копіювати посилання», везе ще й режим
(`?room=КОД&mode=team`): якщо друг відкриє його раніше, ніж кімната ожила, вона
створиться саме тим режимом, а не звичайним.

Правила спільні для всіх режимів: 3 життя, кожен влучний удар — очко, складність
(гравітація) поволі росте з рахунком. У мультиплеєрі гравці **грають разом**:
рахунок, рівень і життя спільні.

## Біоми

Кожен рівень грається в новому місці, і місце — **не лише тло**: у кожного біома
свій вплив на політ кульки. Після п'ятого коло замикається.

| Рівень | Біом | Що змінює | Заміряно |
|---|---|---|---|
| 1 | 🌳 Лука | еталон | падає 269 px за 2 с, зносить убік 14 px |
| 2 | 🏜 Пустеля | гарячий вітер, `swayMul: 2.4` | зносить убік 33 px замість 14 |
| 3 | ❄️ Зима | густе повітря, `dragMul: 1.35` | удар гасне швидше: 182 проти 224 px/с через секунду |
| 4 | 🌌 Ніч | `gulls: false` | чайки сплять, зорі на небі |
| 5 | 🚀 Космос | `gravityMul: 0.6` | падає 167 px замість 269 |

Біом — **чиста функція від рівня** (`biomeAt()`), як і сам рівень від рахунку.
Тому в мультиплеєрі його не треба ні зберігати у світі, ні класти в снапшот:
рахунок і так однаковий у всіх, отже й місце однакове.

Тло перемальовується лише в момент зміни біома, а не щокадру — це десятки
заповнень. Зорі малюються просто в тло (вони нерухомі) з детермінованої
«шумілки», щоб небо не мерехтіло новим візерунком щоразу, коли гравець
повертається в цей біом. Сніг — окремий шар із 70 кружечків, він єдиний
оновлюється кожен кадр.

Колір полів обабіч світу (екран рідко тієї ж пропорції, що й ігрове поле) теж
міняється разом із біомом — інакше вночі гру обрамляли б дві блакитні денні смуги.

Чайку, яка вже летить, ніч не проганяє: спить наступна, а ця долітає. Інакше
птаха зникала б просто в повітрі на переході рівня.

## Рівні

Щоб пройти рівень, треба натапати кульку потрібну кількість разів. Перший рівень —
50 влучань, далі кожен приблизно на 30% довший:

| Рівень | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
|---|---|---|---|---|---|---|---|
| Влучань | 50 | 65 | 85 | 110 | 145 | 185 | 240 |

Прогрес показує смуга вгорі екрана. Рівень і прогрес — **чиста функція від
загального рахунку** (`levelInfo()` у `src/shared/physics.js`), тому в мультиплеєрі
снапшот не везе жодного зайвого поля: клієнт рахує їх сам з рахунку.

## Чайки

Раз на 30 секунд прилітає чайка, наводиться на кульку і клює її. Після укусу
кулька **здувається до 62% розміру і 5 секунд падає рівно вдвічі швидше**, потім
плавно надувається назад. Здута кулька ще й помітно тьмяніша — видно з першого
погляду.

Подвоєння швидкості падіння зроблено чесно через фізику, а не множником на
позицію. Кулька має лінійний і квадратичний опір повітря, тому подвоєна
гравітація сама по собі дала б лише 1.67× (опір росте зі швидкістю). Тому разом
із гравітацією масштабується й лінійний опір — здута кулька менша, отже й
гальмує повітрям слабше. Разом виходить 1.99×, і це фізично послідовно, а не
підігнано.

Якщо кулька впала, чайка зникає і відлік починається наново — інакше птаха
клювала б щойно відроджену кульку.

## Чайка какає, а руки треба мити

За кожен приліт чайка **двічі какає** просто в польоті. Ловить це не кулька, а
долоня: якщо влучило — рука брудна, і поки її не помиєш, кулька з неї **ковзає**.

* Ляпас брудною рукою слабший утричі (`POOP.slapMul`) — заміряно: кулька летить
  958 px/с замість 2610.
* Брудна рука **не заробляє очок** — саме це й жене гравця до відра, а не якесь
  «мінус серце». Це комічна морока, а не кара: сердець тут не забирають.
* По кутках підлоги стоять **два відра з водою** — по одному з кожного боку, щоб
  бігти було недалеко. Долоня торкнулась відра — миттю чиста, без таймера.

Дві дрібниці, знайдені на скріншотах:

1. Відра спершу стояли по 110 px від краю — і ліве ховалось під кнопкою аптечки.
2. Гірше: панелі аптечки й шалу ловили мишу. Ведучи руку в куток, гравець
   заводив курсор на панель, і канва переставала бачити рух — до лівого відра
   було просто не дотягтись. Тепер панелі прозорі для миші (`pointer-events:
   none`), ловлять її лише самі кнопки, а відра відсунуті на 190 px.

## Сходи складності класики

Раніше загрози в звичайному режимі кидались жеребом: шипи випадали з шансом 45%,
чайка прилітала вже на першому рівні. Дві партії поспіль відчувались зовсім
по-різному, а перша хвилина новачка залежала від того, як ляже монета.

Тепер це **сходи**: кожен рівень додає рівно ОДНУ нову загрозу, тож із кожною
знайомишся окремо, перш ніж вона змішається з наступною.

| Рівень | Що додається | Набір загроз |
|---|---|---|
| 1 | — | спокійно: просто не впусти кульку |
| 2 | ⚠ шипи | шипи |
| 3 | 🕊 чайка | шипи + чайка |
| 4 | 🦔 їжачок | шипи + чайка + їжачок |
| 5 | 🪨 камінці | шипи + чайка + їжачок + камінці |
| 6+ | — | усе те саме, але **паузи стискаються** |

Після п'ятого рівня нового вже не додається — натомість інтервали між загрозами
плавно стискаються до **0.55** від початкових і впираються в стелю на 12-му
рівні (`LADDER_SQUEEZE`). Стеля обов'язкова: без неї двадцятий рівень був би не
грою, а стіною.

Сходинка — **чиста функція від рівня** (`ladderAt()`), як і біом. Тому в
мультиплеєрі її не треба ні зберігати у світі, ні класти в снапшот: рівень
рахується з рахунку, а рахунок і так однаковий у всіх. Саме тому з протоколу
зник старий прапорець `spikesOn` — він став похідним.

Дебют нової загрози оголошує **банер, а не влучання**: тій, що саме ввімкнулась,
`greetNewHazards()` ставить повну паузу. Інакше їжачок міг би вибігти вже за
шість секунд (стільки лишає `clearHazards()` після падіння) — тобто раніше, ніж
гравець дочитає, хто це взагалі такий.

Біля номера рівня стоїть коротка пам'ятка з тих самих значків (`⚠🕊🦔🪨`) — видно,
що вже прокинулось, не чекаючи, поки воно прилетить.

Хардкор і тім-ап сходів не мають: у них свої набори загроз з першої секунди
(`rung()` повертає для них `null`), і сходи лише розмили б їхній характер.

## Шипи

У класиці шипи вмикаються **з другого рівня** (див. сходи вище), у хардкорі —
з першого. Із землі вони вилітають угору, і влучання в кульку коштує **два
серця** одразу.

Перед кожним пострілом земля близько секунди тріскається й блимає червоним рівно
там, де вилетить шип. Без цього попередження втрата двох сердець з нізвідки була б
несправедливою — а це дитяча гра. Місце появи береться з розкидом навколо кульки:
шип майже завжди справжня загроза, але кульку встигаєш відвести вбік.

Що рівень із шипами, видно одразу: біля номера рівня стоїть ⚠, а на переході
банер каже «Обережно, із землі летять шипи».

Перший рівень завжди безпечний — там ще вчаться просто тримати кульку в повітрі.

### Шип можна відбити рукою

Долоня збиває шип у польоті: підстав її під вістря — і шип летить назад у землю,
не діставши кульки. Відбитий шип малюється перевернутим і блідим, тож одразу
видно, що він уже не страшний. Відбити — така сама робота, як ляпас, тому долоня
після цього так само на 0.3 с стає **вдвічі повільнішою**. Зняти цей штраф
достроково можна аптечкою (див. нижче).

Шип летить 760 px/с — це до 13 px за кадр, а на просілому кадрі й усі 38. Тому
перевіряється не сама точка вістря, а **весь відрізок, який воно пройшло за цей
кадр** (`handAtSpike`), інакше шип просто перестрибував би долоню.

Порядок перевірок теж не випадковий: спершу долоня, потім кулька. Шип, що за один
крок проходить крізь долоню в кульку, має бути відбитий, а не зарахований як
влучання.

## Монети й магазин

За **кожне влучання по кульці — одна монета** (`COIN.perHit`). За них у меню
відкриваються скіни кульки й перчатки: куплені вдягаються кліком, некуплені
показують ціну і купуються тим самим кліком — окремої кнопки «купити» немає,
бо для дитини менше кроків важливіше за формальність.

| | 🎈/👋 | 💧 | 🍏 | ⚡ | 🪄 | 🥊 | 🧤 | 🪶 |
|---|---|---|---|---|---|---|---|---|
| Ціна | 0 | 80 | 150 | 150 | 250 | 300 | 120 | 200 |

Ціни підібрані під темп гри: перший рівень — це 50 влучань, тож найдешевша
кулька відкривається приблизно за півтори партії, а найдорожча перчатка — за
кілька вечорів.

Монети — **річ особиста** і живуть у `localStorage`, а не у світі: у мультиплеєрі
кожен збирає свій гаманець зі своїх влучань (події прилітають від усіх гравців
кімнати, тож у мережевій грі зараховуються лише ті, де `e.player === net.side`).
Сервер про гаманець не знає взагалі.

Повідомлення магазину («не вистачає 130») показується **під тим самим рядом**,
а не в загальному `#note` внизу картки: картка прокручується, і повідомлення
там просто не побачили б.

Наприкінці партії екран показує, скільки монет зароблено саме за цю гру.

## Скіни кульки

У меню обирається кулька, і це **не лише колір** — у кожної своя здібність,
і кожна чіпляється за свою систему гри:

| Скін | Здібність | Що змінює | Заміряно |
|---|---|---|---|
| 🎈 Класична | еталон | — | падає 173 px за 1.5 с |
| 💧 Синя | падає повільніше | `gravityMul: 0.7` | 123 px за ті самі 1.5 с |
| 🍏 Зелена | міцна | `spikeCost: 1` | шип забирає 1 серце замість 2 |
| ⚡ Жовта | легка рука | `slowMul: 0.5` | штраф долоні 0.15 с замість 0.3 |
| 🪄 Фіолетова | не боїться чайки | `deflateMul: 0.4` | здувається 2 с замість 5 |

Множники навмисно скромні: скін має міняти відчуття гри, а не вимикати
складність. Тому жоден із них не робить кульку невразливою — синя все одно
падає, зелена все одно втрачає серце, жовта все одно має штраф.

Скін живе **у світі**, а не в клієнті (`w.skin`, `setSkin()`): здібності мусять
бути однакові для всіх, хто грає в цій кімнаті, інакше в одного гравця кулька
падала б повільніше, ніж у другого. У мультиплеєрі кулька одна, тож і скін один —
діє вибір того, хто обрав останнім (`{t:'skin', i}`).

Колір здутої кульки не задається окремою константою, а рахується від кольору
скіна (`lerpColor(color, 0x9aa4ab, 0.45)`) — інакше кожен новий скін вимагав би
ще однієї константи.

Вибір зберігається в `localStorage`, тож дитина не шукає «свою» кульку щоразу
наново, а кулька-заставка в меню одразу перефарбовується — видно, що саме обираєш.

## Скіни перчаток

Перчатка, на відміну від кульки, **річ особиста**: скін живе в долоні
(`h.glove`), а не у світі, тож у мультиплеєрі кожен грає своєю.

| Перчатка | Здібність | Що змінює | Заміряно |
|---|---|---|---|
| 👋 Класична | еталон | — | радіус 54, ривок 1000 px за 0.43 с |
| 🥊 Боксерська | шал | кнопка «Шал» / клавіша `B` | 5 с зовсім без кулдауну, 2 рази на рівень |
| 🧤 Воротарська | більша | `sizeMul: 1.25` | радіус 68 замість 54 |
| 🪶 Легка | швидша | `speedMul: 1.3` | той самий ривок за 0.35 с |

Розмір воротарської росте і у фізиці, і в графіці рівно однаково (`gloveScale()`
проти `h.r`), тож видима рука і рука, якою б'єш, — це одне й те саме.

### Шал боксерської перчатки

5 секунд, коли удари **взагалі не втомлюють руку**. Кнопка внизу зліва або
клавіша `B`, 2 заряди на кожен рівень (`RAGE`), заряди видаються наново, як в
аптечки.

Головне тут не швидкість, а рахунок: очко зараховується лише свіжій долоні
(`scores` дивиться на той самий `slow`), тому без кулдауну зараховується **кожен**
удар підряд. Заміряно на 5 секундах безперервного биття знизу: 5 очок без шалу
проти 12 із шалом, і найбільший штраф за весь час — рівно 0.

Поки шал триває, другий заряд не витрачається, а перчатка пульсує вогняним
кільцем — видно і гравцеві, і сусідові по кімнаті.

## Аптечка

🩹 **Аптечка лікує двічі: повертає серце і знімає з руки штраф за удар.**
На кожному рівні 5 зарядів, кнопка внизу зліва (або клавіша `H`).

Друге і є головним у бою: відбив шип — рука обважніла на 0.3 с; натиснув аптечку —
рука знову швидка, не чекаючи, поки штраф збіжить сам.

* Заряди на новому рівні **видаються наново, а не додаються** — інакше обережний
  гравець приходив би на десятий рівень із півсотнею аптечок у кишені.
* Заряд не витрачається даремно: якщо і серця повні, і рука свіжа, натискання
  нічого не робить, а кнопка блідне. Досить чогось одного — важкої руки при
  повних серцях цілком достатньо, щоб аптечка спрацювала.
* Понад `RULES.lives` (3) серця не набити — аптечка лише повертає втрачене.
* У мультиплеєрі аптечка **спільна на кімнату**, як і самі серця, тож рішення про
  заряд ухвалює сервер (`{t:'medkit'}` → `useMedkit(world, handId)`), а не клієнт.
  Руку він відпускає саме тому, хто натиснув, — тому й кнопка дивиться на свою
  долоню, а не на будь-чию. У локальній грі кнопка одна на всіх, тож там аптечка
  відпускає всі долоні.

`useMedkit()` повертає подію, а не кладе її у `w.events`: аптечку тиснуть між
кроками світу, а `step()` чистить події на початку кожного кроку — подія
загубилась би, не дійшовши ні до звуку, ні до снапшота.

## Хардкор

Хардкор — **окремий режим, а не галочка складності**. Загрози в нього й у класику
завозить той самий код, але вмикають його різні джерела: у хардкорі це прапорець
`w.hardcore` (усе з першої секунди), у класиці — сходинка рівня (`rung()`, яка для
хардкору й тім-апу повертає `null`). Різниця не в наявності камінців, а в темпі:
класика доходить до повного набору аж на п'ятому рівні, хардкор починає з нього.

| | Звичайна | Хардкор |
|---|---|---|
| Серця | 3 | **2** |
| Аптечок на рівень | 5 | **2** |
| Влучань на перший рівень | 50 | **25** |
| Шипи | з 2-го рівня (сходи) | **завжди, з першого** |
| Чайка | з 3-го рівня, раз на 30 с | **з першого, раз на 18 с** |
| Їжачки-вороги | з 4-го рівня | **з першого** |
| Камінці з неба | з 5-го рівня | **з першого** |
| Темп загроз | стискається до 0.55 до 12-го рівня | **сталий** |
| Чим б'єш | перчатка | **персонаж** |
| Валюта | 🪙 монети за влучання | **☠ черепи за пройдені рівні** |

Рівні вдвічі коротші навмисно: 50 влучань із двома серцями під камінням — це не
рівень, а вечір, і черепи за нього чекали б надто довго.

Складність росте з рахунком різкіше (`gravityRamp` 2.6 проти 1.6, стеля 700
проти 520). Заміряно, падіння кульки за 1.2 с:

| Рахунок | 0 | 100 | 200 |
|---|---|---|---|
| Звичайна | 125 px | 198 px | 246 px |
| Хардкор | 125 px | 236 px | 320 px |

На нульовому рахунку вони однакові — це не помилка: обидві починають з тієї
самої `BALLOON.gravity`, і розходяться саме з рахунком.

## Камінці

Головна хардкор-загроза, і навмисно **дзеркальна до шипів**: шип летить із
підлоги вгору, камінь падає з неба вниз. Небезпечним стає рівно той простір над
кулькою, куди гравець і б'є, — доводиться вибирати між ударом і ухилянням, а не
просто молотити знизу.

Попередження є й тут, як у шипа: камінь спершу висить угорі, а під ним світиться
**стовп на всю висоту поля** — видно не сам камінь, а колонку, куди він упаде.
Разом виходить 0.9 с попередження плюс 0.92 с падіння: **1.82 с**, щоб відвести
кульку або підставити персонажа.

Розкид місця появи (`spread` 420) ширший за саму кульку — і це головне число
всього режиму. З вужчим (міряно на 300) камінь накривав нерухому кульку майже
завжди: пасивний бот втрачав обидва серця за 15 секунд, і режим виходив не
важким, а безвихідним. Тепер, за 620 камінців на нерухомій кульці, накривають
**57%** — тобто відводити треба, але й відвести встигаєш.

Камінь **можна збити персонажем**, як шип рукою. Збитий летить у бік замаху,
малюється блідим і вже нікого не чіпає. Перевіряється, як і в шипа, не точка, а
весь відрізок шляху за кадр: камінь розганяється до 600+ px/с, тобто до 10 px за
кадр, і на просілому кадрі просто перестрибнув би персонажа.

## Хардкор-персонажі

У хардкорі кульку тапає не долоня, а персонаж. Керування те саме (миша / WASD,
у кімнаті — свій персонаж у кожного), різниця у здібностях. Персонаж — **річ
особиста**, як перчатка: живе в руці (`h.char`), а не у світі, тож у
мультиплеєрі кожен грає своїм.

| Персонаж | Ціна | Що дає |
|---|---|---|
| 🦝 Єнот | 0 | еталон хардкора |
| 🦔 Їжачок | ☠ 12 | підкидає кульку без замаху; шипи й камінці збиває здалеку і без утоми |
| 🦨 Ванючка | ☠ 20 | чайки не прилітають зовсім |
| 🛡 Броненосець | ☠ 28 | шипи розбиваються об спину без утоми; раз на рівень спина не дає кульці впасти |
| 🐀 Пацюк | ☠ 35 | ривок 1000 px за 0.28 с замість 0.40 |

**У персонажів немає мінусів.** Спершу були: їжачок колючками лускав власну
кульку, ванючка сама собі бруднила лапу, пацюк був на чверть менший. Задум був
такий, що мінус робить вибір вибором, а не покупкою «хто дорожчий, той кращий».
На практиці вийшло інакше: куплене за кілька вечорів має тішити, а не
підставляти. Тому колючі неприємності переїхали туди, де їм і місце, — у
**ворогів, що приходять ззовні** (див. «Їжачки-вороги»), а гроші тепер купують
тільки плюси.

### Їжачок б'є без замаху

Здібність спершу задумувалась як «сильніший ляпас» (`slapMul` 1.4), і на цьому
знайшлась цікава річ: **на повному замаху сильніший удар не працює взагалі**.
Кулька має власну стелю швидкості точки (`BALLOON.maxSpeed`), і зайвий імпульс
просто зрізається. Заміряно підйом кульки від одного удару:

| Швидкість руки | Єнот | Їжачок |
|---|---|---|
| 300 px/с | 2 px | **54 px** |
| 800 px/с | 60 px | **113 px** |
| 2600 px/с (повний замах) | 86 px | 124 px |

Тому здібність описана чесно тим, чим вона є: не «сильніший удар взагалі», а
«**не треба замахуватись**». І це саме те, що потрібне в хардкорі: кожен
зекономлений замах — це час на ухиляння від каменя.

### Ванючка відганяє чайок

Сморід — річ спільна на все поле: досить одного ванючки в кімнаті, щоб чайки не
прилітали до всіх. Інакше птасі довелося б якось «вибирати», кого вона бачить.
Заміряно за 120 секунд: у єнота 6 чайок, у ванючки **0**.

### Броненосець не дає кульці впасти

Обидві його здібності — це одна річ, видима з двох боків: **тверда спина**.

Перший бік — шипи. Броненосець відбиває їх, як їжачок, не втомлюючись, і дістає
трохи далі за всіх: панцир ширший за лапу. Заміряно, наскільки вбік від шипа
може стояти персонаж, щоб усе одно його збити, і скільки після цього рука
лишається обважнілою:

| Персонаж | Дістає вбік | Втома після відбивання |
|---|---|---|
| 🦝 Єнот | 75 px | 0.30 с |
| 🦔 Їжачок | 93 px | 0 |
| 🛡 Броненосець | **101 px** | 0 |

Другий бік — падіння. Це **єдина здібність у грі, яка вмикається вже після
програшу епізоду**: кулька торкнулась підлоги, і замість втрати серця вона
відскакує від підставленої спини. Заміряно в однаковому світі з нерухомою
рукою: у єнота перше серце згорає на 2.67 с, у броненосця — на **7.02 с**;
кулька відскакує на 472 px над підлогою і тримається в повітрі ще 4.33 с.

Три рішення, без яких це було б зламано:

* **Раз на рівень.** Якби спина ловила кожне падіння, гра перестала б
  називатись «не впусти кульку»: з двома серцями хардкора нескінченний рятунок
  зняв би з режиму саме те, чим він хардкор. Заряд поновлюється на новому
  рівні, як аптечки й шал.
* **Рятує найближчий.** У кімнаті може бути кілька броненосців, і спину
  підставляє той, хто ближчий до місця падіння, — дзеркально до тім-апа, де
  серце втрачає теж найближчий. Відстань при цьому нічого не забороняє:
  броненосець котиться клубком, і для нього підставитись з іншого краю екрана —
  питання того самого моменту.
* **Відскок жорсткий.** Усім точкам оболонки ставиться одна швидкість угору
  (`SHELL.bounce`), а не імпульс у точці дотику. Панцир на те й панцир, що не
  мнеться: кулька йде від нього рівно вгору, а не закручується, як від ляпаса.

Зміна персонажа розрізняє два випадки. **Не витрачений** на цьому рівні панцир
просто стає таким, який дає новий звір: інакше броненосець, обраний у меню
кімнати (а вибирають його вже після приєднання), лишався б без панцира аж до
другого рівня. **Витрачений** лишається витраченим — повернути його, двічі
перемкнувши звіра, не можна. Саме для цього різниці й потрібен прапорець
`h.shellSpent`, який скидає лише новий рівень або нова партія.

## Їжачки-вороги

Єдина загроза, що приходить **по землі**. Шип вилітає з підлоги вертикально,
камінь падає з неба, чайка кружляє — а їжак просто вибігає збоку, доганяє кульку
по горизонталі й підстрибує. За ним видно, куди він цілиться.

Серця він не забирає. Влучив — **б'є кульку додолу**, і далі все вирішує, чи
встигне хтось її підхопити. Заміряно: після удару кулька йде вниз зі швидкістю
**874 px/с**. Тобто це не кара, а раптова робота для рефлексів.

Головне правило проти нього одне: **тримай кульку вище**. Їжак стрибає, лише
коли справді дістане, і стеля стрибка рахується з тієї самої фізики, що й сам
стрибок (`hogReachY()` = v²/2g), а не окремою константою — інакше після будь-якої
правки швидкості підказка почала б брехати. Заміряно за 90 секунд:

| Висота кульки | Прибігло | Стрибків | Влучань |
|---|---|---|---|
| y = 250 (високо) | 6 | 0 | **0** |
| y = 400 | 6 | 0 | **0** |
| y = 520 (стеля стрибка) | 6 | 6 | 6 |
| y = 600 (низько) | 6 | 6 | 6 |

Їжачки бігають у **хардкорі й тім-апі**; дитяча гра лишається без них — заміряно,
у звичайному режимі за 120 секунд не прибіг жоден.

Після падіння кульки їжака з поля прибираємо (доганяти щойно відроджену кульку
нечесно), але відлік скидаємо лише наполовину: з повним інтервалом гравець, який
часто впускає кульку, взагалі ніколи б їх не побачив.

## Черепи

Валюта хардкора. Черепи дають **не за влучання** (це робота монет), а лише за
**пройдений хардкор-рівень** — і тільки в хардкорі:

| Рівень | 1 | 2 | 3 | 4 | 5 | 6 |
|---|---|---|---|---|---|---|
| Черепів | 3 | 5 | 8 | 12 | 20 | 31 |

Тому персонажа не «накопичиш між ділом» у дитячій грі: їжачок (☠ 12) — це три
пройдені хардкор-рівні, пацюк (☠ 35) — п'ять. Монети на черепи не міняються, і
навпаки: це дві окремі валюти двох окремих ігор.

Гаманець, як і монети, живе в `localStorage` і сервер про нього не знає. Рівень
у кімнаті спільний, тож черепи за нього, на відміну від монет, **не фільтруються
по гравцеві**: проходять рівень усі разом.

Рекорд у хардкорі теж окремий (`balloon-best-hardcore`): рівні там удвічі
коротші, і спільний рекорд порівнював би непорівнянне.

## Хардкор у мультиплеєрі

Кімната або хардкорна, або ні — **світ у ній один**, тож грати в ній у різні
ігри неможливо. Режим задає той, хто кімнату створив; хто приєднався пізніше,
дізнається з `welcome`, куди саме він потрапив, і бачить про це підпис
(«Ця кімната хардкорна ☠»). Персонажа кожен лишає свого.

Тому режим, з поля якого тиснеш «Приєднатись», — це лише **побажання на випадок,
коли кімнати ще нема**: код з тім-ап-острова так само заведе тебе в хардкорну
кімнату, просто з підписом про це. Створює ж кнопка «Створити кімнату» завжди
кімнату свого острова.

## Тім-ап

Третій режим — кооператив, і тримає його одне правило:

> **Тапнувши, ти не можеш тапнути вдруге, поки кульку не зачепить хтось інший.**

Через нього гра перестає бути про власну спритність. Кулька мусить ходити по
руках, і кожен удар — це передача: влучити мало, треба ще й лишити її там, звідки
дістане сусід.

| | Звичайна | Тім-ап |
|---|---|---|
| Серця | 3 на всіх | **по 3 в кожного** |
| Влучань на перший рівень | 50 | **35** |
| Шипи | жереб 45% | **немає** |
| Пастки | — | **павутина і смола** |
| Їжачки-вороги | — | **є** |
| Аптечок на рівень | 5 | **4** |
| Валюта | 🪙 за влучання | **🤝 за паси** |

Грати можна вдвох за одним комп'ютером або кімнатою до чотирьох. Одному — не
можна, і кнопки такої немає: пасувати нема кому.

### Заборонений гравець — безтілесний

Той, хто щойно тапнув, не «б'є без сили» — кулька просто **пролітає крізь нього**,
і він малюється привидом із пунктирним кільцем. Видно з першого погляду, чия
зараз черга.

Півзаходу тут бути не могло: «лишити руку перешкодою, але прибрати удар» у цій
грі вже пробували для кулдауну (див. «Сила ляпаса») — рука тягне за собою точки
контакту, решта оболонки відстає, і кульку рве на шматки зі швидкостями під
160 000 px/с. Тому єдиний чесний спосіб «не можна тапнути» — це справді не бути
на шляху.

Правило перевірено ботами: на **986 ударах — 0 порушень**. Ще 49 разів той самий
гравець бив двічі поспіль, і всі 49 — це виняток нижче.

### Виняток від глухого кута

Якщо бити більше **нема кому** — усі інші вибули або сидять у павутині, — заборона
з останнього знімається. Без цього єдиний живий гравець просто дивився б, як
кулька падає, бо пасувати нікому.

### Серця особисті, і втрата адресна

По три серця в кожного (з перком — чотири). Щоб це щось означало, втрата мусить
бути адресною: якби на падінні серце втрачали всі, вони й вибували б одночасно —
тобто це були б ті самі спільні три серця, тільки намальовані вчетверо.

Тому серце втрачає той, хто **міг бити і був найближче** до місця падіння: не той,
хто щойно пасував (йому й не можна було), і не той, хто застряг у павутині. Хто
втратив усі — вибуває з поля, решта грає далі; партія кінчається, коли вибули всі.

Шипів у тім-апі немає зовсім: у режиму є свої пастки, і дві системи загроз
одночасно перетворили б екран на кашу. Заразом це прибрало помилку, яку видно
лише в бою: шип ішов спільним `loseLives()` і списував `w.lives`, якого в цьому
режимі не існує, — партія могла обірватись при повних серцях у всіх.

## Паси, серії та командні бафи

Пас — це удар, перед яким бив **хтось інший**. Перший удар після падіння пасом не
рахується: передавати ще не було кому.

Кожні п'ять пасів команда отримує баф. Він саме командний, а не тому, хто пасував:
пас — робота двох, і особиста нагорода штовхала б «забирати» паси собі, тобто
рівно до того, що цей режим має прибрати.

| Серія | Баф | Що дає | Заміряно |
|---|---|---|---|
| 5 пасів | 👟 Швидкі ноги | уся команда швидша | `speedMul` ×1.35 |
| 10 пасів | 🧤 Великі лапи | у всіх більший радіус | 70 замість 54 |
| 15 пасів | 🛡 Щит | одна пастка мине кожного | заряд особистий |

Кулька впала — серія обнуляється, і відлік починається з нуля. Бафи, які вже
горять, доживають свій час: відбирати їх разом із серцем було б подвійною карою.

## Пастки

Дві, і навмисно різні: одна б'є по **гравцеві**, друга — по **кульці**.

### Скільки їх

Спершу пастки сипались рівно: одна за 7-12 секунд, і так на першому рівні, і на
дванадцятому. Через це тім-ап з часом ставав спокійнішим за класику, де кожен
рівень додає нову загрозу. Тепер пауза між ними тане з рівнем (−7% за рівень,
не нижче 45% від повної), а з третього рівня пастки іноді приходять **парою** —
і саме різною: павутина по гравцеві плюс смола по кульці одночасно.

Заміряно на хвилину гри (шість прогонів на кожен рівень):

| рівень | було | стало | максимум на полі |
|---|---|---|---|
| 1 | 5.5 пастки/хв | **7.3** | 3 (було 2) |
| 5 | 5.0 | **12.3** | 5 |
| 9 | 5.3 | **13.3** | 6 |
| 12 | 5.3 | **14.5** | 5 |

### 🕸 Павутина

Ловить того, хто в неї влетів: він не може ні тапати, ні рухатись. Тримає 3.6
секунди — але **сусід визволяє дотиком**, і це єдине місце в грі, де гравці
допомагають один одному руками, а не просто разом б'ють кульку. Заміряно:

| | тримає |
|---|---|
| сам вибирається | 3.60 с |
| з перком ✂️ | 2.20 с |
| сусід прибіг | 0.13 с |

Павутина ще й **полює**: у 7 випадках з 10 вона виникає не де трапиться, а
поруч із чиєюсь долонею. «Поруч» — це кільце в 140-280 px: ближче вона ловила б
у ту ж мить, коли з'явилась, і ухилитись було б неможливо, далі — не відрізнялась
би від випадкової. Радіус самої павутини 66 px замість 58.

Цінна вона саме тим, що ламає чергу пасів: поки один у павутині, решта мусить
передавати меншим колом.

### 🫧 Смола

Хмара, в якій кулька грузне: важчає у 2.3 раза, а удари в ній в'язнуть удвічі.
Сама хмара теж більша — 130 px замість 115.

Перший підхід був рівно навпаки — «густе повітря» (потроєний опір). Заміряно, що
вийшло: кулька в такій хмарі падала **повільніше**, а підйом від удару був навіть
на 5 px більший, ніж у чистому повітрі. Тобто пастка допомагала тримати кульку.
Тепер це не опір, а вага і в'ялий ляпас:

| | чисте повітря | у смолі |
|---|---|---|
| провалитись на 200 px | 1.62 с | **1.07 с** |
| підйом від удару знизу (повний замах) | 86 px | **17 px** |
| розмашистий удар убік | — | **вибиває з хмари за 0.18 с** |

Останній рядок і є суттю: смола не «нічого не вдієш», а «бий не вгору, а вбік».

Числа в таблиці зняті при попередній вазі (×2.0). Після переробки смола важча
(×2.3) і ляпас у ній в'ялішій (0.5 замість 0.6): на тому самому стенді падіння
крізь хмару пришвидшилось ще на десяту частину.

Валюта тім-апа. Дають за **паси**, а не за влучання: у цьому режимі цінне не
«я влучив», а «ми передали». Жетон за кожен пас плюс п'ять за кожен командний
баф, і — на відміну від монет — **усім одразу**, бо пас це робота двох.

Магазин тім-апа продає не скіни, а командні переваги. Перк не вдягається замість

всі куплені.

|---|---|---|---|
| ⏳ Довші бафи | 🤝 40 | бафи тримаються 12 с замість 8 | на всю команду |
| ✂️ Слабка павутина | 🤝 70 | павутина тримає 2 с замість 3 | на всю команду |
| 💗 Запасне серце | 🤝 120 | четверте серце | тільки тобі |

Два з трьох — командні: досить, щоб хтось один приніс покупку в кімнату, інакше
кооператив перетворився б на змагання гаманців. Третій лишається особистим, бо й
серця тут особисті.

## Тім-ап у мультиплеєрі

Кімната або тім-ап, або ні — світ у ній один, як і в хардкорі. Правило черги
рахує **сервер**: у снапшот їде готове «можеш / не можеш» (`locked`), тож клієнту
не треба знати, хто ще живий і хто в павутині. Перевірено на чотирьох клієнтах —
серія в 94 паси, 18 бафів, і події збіглися в усіх до однієї.

## Як влаштована фізика

`src/shared/physics.js` — один і той самий код працює і в браузері, і на сервері.

Кулька — замкнене кільце з 26 точкових мас. Форму тримають три сили:

1. **Пружини оболонки** між сусідніми точками. Довжина спокою кожного ребра взята
   з форми «краплі», тому кулька повертається саме в неї, а не в коло.
2. **Тиск повітря** `P = pConst / A`. Стискаєш кульку → площа падає → тиск росте →
   вона випинається деінде. Константу підібрано за 2D-законом Лапласа `T = P·R`,
   щоб тиск рівно врівноважував натяг оболонки на потрібному радіусі.
3. **Слабкі «спиці»** до центру мас: тримають силует і страхують оболонку від
   вивертання при дуже сильному ударі.

Ступінь надутості живе в одному числі `balloon.inflate` (1 — повна кулька).
Воно масштабує довжини спокою, спиці та тиск (останній — як квадрат розміру,
бо площа росте квадратично). Тому здування — це не окремий режим, а той самий
розрахунок з іншим коефіцієнтом.

Плюс гравітація, лінійний і квадратичний опір повітря (тому різкий удар швидко
гасне, як у справжньої кульки) і легкий протяг у кімнаті.

Інтегрування — напівнеявний Ейлер, 8 підкроків на кадр. Долоня рухається
всередині підкроків, інакше швидкий ляпас просто проскакував би крізь оболонку.

**Зіткнення з долонею** рахується по ребрах, а не по вершинах: шукаємо найближчу
точку відрізка, а імпульс розкладаємо на дві вершини з вагами `1-t` і `t`.
Половина імпульсу йде в точку контакту (вм'ятина), половина — рівномірно всій
кульці, щоб вона відлітала цілком. Окремо обробляється випадок, коли кулька
«проковтнула» долоню (вона більша за неї): тоді кулька зсувається цілком,
бо виштовхування одного ребра дало б лише вм'ятину, у якій долоня застрягне.

Сила удару залежить від швидкості долоні — тому кулька летить саме туди, куди
нею замахнулись, а ковзний удар ще й закручує оболонку.

## Мультиплеєр

Фізику рахує сервер (авторитетна симуляція, 60 Гц), снапшоти розсилає 30 разів
на секунду. Клієнт малює стан на 90 мс у минулому й інтерполює між двома
снапшотами — тому кулька рухається плавно навіть при джитері мережі. Власну
долоню клієнт малює локально тим самим згладжуванням, що й сервер, тож керування
не відчуває пінгу.

У кімнаті до **4 гравців**, кожен своїм кольором (помаранчева, блакитна, зелена,
фіолетова долоня). Номер місця видається найменший вільний, тож той, хто вийшов,
звільняє своє місце для наступного.

Поки в кімнаті один гравець, симуляція на паузі — інакше він розгубив би життя,
чекаючи на друзів. Якщо з чотирьох виходить один, гра просто триває далі.

### Обрив зв'язку

Кімната на сервері живе, поки в ній лишився хоч хтось, тож обрив мережі — це не
кінець партії. Клієнт сам повертається за тим самим кодом: десять спроб із
паузою, що росте (разом близько 40 секунд). Поки триває повернення, сцена
завмирає на останньому снапшоті, а не блимає порожнім небом, і зароблені за
партію монети лишаються на місці. Здаємось лише після останньої спроби — тоді
гравець іде в меню.

Сорок секунд узяті не зі стелі: після справжнього обриву сервер ще тримає наше
старе місце, поки не зрозуміє, що на ping ніхто не відповідає. Тому перевірку
скорочено до 8 секунд — щоб той, хто повертається, застав своє місце вже
вільним, а не «кімнату повну» з власного привида.

### Ключі снапшота унікальні

Снапшот — це рукописний об'єкт із двобуквеними ключами, і два однакові ключі в
ньому JavaScript не вважає помилкою: другий мовчки затирає перший. Саме так
скін кульки (`sk`) колись затер скунсів (`sk`), і клієнт падав на першому ж
кадрі онлайн-гри — `(число).map is not a function` усередині інтерполяції.
Тепер скін їде як `si`. Додаючи поле в снапшот, перевір, що такого ключа там ще
немає.

## Волейбалл

Окрема прямокутна картка Волейбалл у головному меню відкриває вибір: проти бота
або онлайн за кодом кімнати. Волейбалл-кімната вміщує до 8 гравців — по 4 в
помаранчевій і синій командах. Новачок автоматично потрапляє в меншу команду.
Почати можна один на один, решта може доєднатись пізніше. Класична,
хардкорна та тім-ап кімнати, як і раніше, — до чотирьох.

Кожен керує долонею на своїй половині майданчика. М’яч потрібно перекинути
над сіткою: дотик до підлоги на половині суперника дає одне очко. Бічні стіни
відбивають м’яч, очко дає саме підлога. Матч триває до 5 очок; після розіграшу
м’яч подається на половину того, хто пропустив. Миша, дотик або WASD керують
своєю долонею; усі партнери мають однаковий колір команди й спільний рахунок.

Бот має затримку реакції та ті самі обмеження швидкості й зіткнень, що й гравець.
Куплені здібності та випадкові небезпеки в цьому режимі не діють. Сервер
сам рахує очки, зіткнення і переможця. Якщо одна команда залишилася без гравців, матч стає
на паузу; при поверненні суперника рахунок зберігається. Кнопка «Ще раз» починає новий матч.

Фізика режиму: `src/shared/basketball.js`. Перевірки без мережі:

```bash
node tests/basketball.test.js
node tests/basketball-rooms.test.js
```

Онлайн потребує запущеного сервера (`npm run share` для публічного тунелю).
Після зміни правил потрібно перезапустити сервер і опублікувати клієнт.

## Баскетбол і спорядження у спортивних режимах

У меню є окремий **Баскетбол**: два кошики, рух усім майданчиком, кидок
дотиком руки до м’яча. Влучання згори дає 2 очки; матч триває до 10.
М’яч відскакує від підлоги, обода та щита. Волейбалл зберігає сітку й матч до 5.
Обидва режими підтримують бота (Ізі / Мідіум / Хард) та кімнати до 4 на 4.

Кнопка «Перчатки та скіни» відкриває спільний магазин. Вибране спорядження
діє в обох спортивних режимах і зберігається після перезапуску матчу.
У цих режимах воно косметичне: здібності зі звичайної гри не застосовуються.
Для онлайн-баскетболу потрібно оновити і клієнт, і сервер. Внутрішній код
нового режиму — `hoops`; `basketball` збережено для сумісності волейбольних кімнат.

### Боти в кімнатах і спостерігачі

Під час створення баскетбольної кімнати прапорець «Заповнити вільні місця
ботами» формує команди 4 на 4. Новий гравець замінює бота, після виходу
гравця бот повертається. Боти мають позначку «БОТ» та складність Мідіум.

У головному меню «Спостерігач» відкриває перегляд наявної кімнати за кодом.
Спостерігач не займає місце гравця, не керує руками й не змінює матч.
Перетягування мишкою або пальцем рухає огляд, коліщатко змінює масштаб,
подвійний клік показує весь майданчик. Рахунок залишається на місці.
Посилання спостерігача містить `watch=1`; роль зберігається при перепідключенні.
Кімната підтримує до 32 спостерігачів. Для цих функцій слід оновити сервер
і клієнт разом.

## ⚽ Футболл

Новий режим `football`: поле з видом зверху, дві команди по 4 футболісти,
матч до 5 голів. У меню є локальна гра з ботами трьох складностей і кімнати
за кодом. У локальному матчі складність стосується суперників: свої напарники
завжди середнього рівня. Легкі боти повільніше реагують і частіше промахуються;
складні точніше б’ють та прогнозують перехоплення. Воротарі також залежать
від складності. У кімнатах боти середнього рівня.
Прапорець заповнення ботами дозволяє почати кімнату самому:
друзі замінюють ботів при вході, після виходу бот повертається.

- WASD або стрілки — рух; без м’яча можна рухатись за мишкою чи пальцем.
- Підійди до м’яча, щоб заволодіти ним; біля суперника можна відібрати м’яч.
- З м’ячем вказівник керує прицілом, а клавіші — рухом.
- Клік або пробіл — удар у напрямку пунктирної стрілки. На сенсорному
  екрані наведи пальцем і відпусти його, щоб ударити.
- Помаранчеві атакують праві ворота, сині — ліві. Воротарі-боти захищають
  ворота, польові гравці переслідують м’яч і займають позиції.

Посилання `?mode=football` запускає локальний матч. Для кімнат потрібно
оновити клієнт і сервер; сервер розраховує рух, володіння м’ячем та голи.

## 🛠 Власні рівні

Меню «Мої рівні» відкриває локальний редактор для класики, хардкору,
тім-апа, баскетболу, волейболу та футболу. Вибери гру, назву, ціль і темп
(0,5–1,5×), а старт м’яча вкажи на схемі або координатами.

Для кульки можна задати 1–10 життів, увімкнути чи вимкнути звичайні загрози
режиму та грати одному або вдвох; тім-ап завжди для двох. Рівень завершується
перемогою після заданої кількості влучань. Для спортивних ігор є команди
від 1 на 1 до 4 на 4 та складність суперників; напарники середнього рівня.

«Зберегти» зберігає до 30 рівнів у поточному браузері, «Грати» запускає поточні
налаштування, навіть якщо їх ще не збережено. Вибір зі списку дозволяє
редагувати наявний рівень. Кнопка «Новий» створює окремий запис. Перезапуск
матчу зберігає власні правила. Ці рівні запускаються локально, без кімнат.


## Нові ігри Shelter Games

Футбол 4×4 до 5 голів: м’яч має повністю перетнути лінію воріт; вихід за поле дає аут, кутовий або удар від воріт. Офсайд перевіряється на пасі та прийманні. F або екранна кнопка — підніжка: штрафний/пенальті та жовта картка, друга жовта вилучає гравця. Це скорочена аркадна адаптація правил, без 90-хвилинного таймера та повної симуляції суддівства.

Окремий локальний «Футбол без правил» має піксельну графіку, підніжки з коротким падінням і ботів, які теж можуть збити суперника. Інші ігри зберігають звичайну графіку.

Пінг-понг — матч проти бота до 7 очок. Арканоїд — 40 блоків і 3 життя. Ловець зірок — збери 20 зірок, уникаючи бомб. Керування: мишка, дотик або стрілки; у кожній грі є повтор і вихід у меню.


## Аркади та рівні

У меню «Аркади та рівні» є 13 аркад із 5 рівнями кожна (65 рівнів). До пінг-понгу, арканоїда й ловлі зірок додані змійка, «Знайди пару», кротобій, бігун, метеорний дощ, космічний захисник, лабіринт, тир, політ пташки та перегони.

Перемога відкриває наступний рівень саме цієї гри. Відкриті рівні зберігаються локально, а пройдені можна вибрати повторно. Кожний рівень має власну палітру та параметри: швидкість, кількість цілей, розкладку блоків, розмір лабіринту, кількість пар або перешкод. Лабіринти генеруються зі зв’язаними проходами; усі ключі й вихід доступні.

Перед початком показуються правила та кнопка «Грати». Є пауза (P), повтор, наступний рівень, вихід (Escape), керування мишкою/дотиком і екранні кнопки. При переході в іншу вкладку гра стає на паузу. Для змійки й лабіринту використовуй стрілки, WASD або екранні напрямки; для стрибка, польоту та пострілу — пробіл або «Дія». Картки та кротів обирай кліком/дотиком.

Механіка аркад відокремлена від малювання: `src/shared/arcade.js`, `src/client/arcade-view.js`, `src/client/arcade.js`. Перевірка: `npm test`, `npm run build`.
